# 96-01 — Per-cycle uptime recorder

## action
`backend/green_uptime.record_cycle()` appends one JSONL line per green cycle
(`ts`, `ok`, `exit_code`, `live_count`, `empty_reason`, `duration_s`) to
`data/green_uptime.jsonl`, rotating at 2 MB with one previous generation.

**Owner of the record:** `scheduler_service._record_green_uptime()`, not the
child process. Two failed attempts before this landed:
1. backend worker — measured only manual `/api/admin/run/green` calls, so the
   soak read `cycles: 1` while the loop ran every minute;
2. `scrape_green.py` itself — the watchdog kills it with `proc.kill()`, so its
   `finally` never runs and the record was lost on every timed-out cycle.

The parent always survives and always knows the outcome.

## acceptance
- [x] one record per green cycle, including timed-out and kill-triggered runs
- [x] rotation at 2 MB, torn lines skipped
- [x] no double counting (child and backend record nothing)
