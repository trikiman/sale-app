# 97-02 — Route-aware preflight and bridge-first scheduling

## action
1. `vless/preflight.probe_bridge_alive()` tries URnetwork (10809) first, then the
   balancer (10808); `ProbeResult.route` names the winner; the 30 s cache is keyed
   by route so a healthy UR never vouches for a dead balancer.
2. `vless/urnetwork.proxy_candidates()` returns URnetwork before the env/VLESS
   fallback.
3. `scheduler_service._prepare_proxy_connectivity()` uses whichever bridge
   answered instead of insisting on UR, and only falls back to the pool when every
   bridge fails.
4. `GET /api/admin/egress-probe` exposes the per-route verdict over HTTP, because
   SSH to the box is blocked by DPI and "is the bridge working?" was otherwise
   unanswerable.
